# VF2 与 LS2K1000LA 串口输入延迟修复和验收

VF2 GMAC1 与串口两项改动的原问题、根因和优化路径总览见
[VF2 GMAC1 与双板串口交互优化总结](../../summaries/星光二号板网卡与串口优化总结.md)。

## 1. 现象与定位结论

本次问题在 VisionFive 2 和 LS2K1000LA 上表现一致：U-Boot 输入正常，进入 MOSS shell
后单键回显变慢，空闲和持续输出时都能观察到。因此问题落在两块板共用的 MOSS TTY、调度和
同步串口输出路径，而不是主机端 USB 串口、线材或网卡驱动。

修改前存在三段可叠加的等待：

1. UART RX IRQ 唤醒 `tty-reader` 时只把任务放回运行队列，不请求抢占。当前调度频率是
   100 Hz，RR 时间片为 5 tick，忙核上的单次额外等待可达到约 50 ms。
2. 两套板级 UART 都在整个 `write_bytes()` 期间持有 `SpinNoIrq`。115200 8N1 每个字符
   需要约 86.8 us，1 KiB 同步输出本身约需 89 ms，期间同核 RX IRQ 无法运行。
3. N_TTY 对输入逐字符调用一次回显写，日志层也在格式化整条记录期间关闭本地 IRQ，进一步
   放大调度和锁竞争成本。

## 2. 修复后的数据路径

RX IRQ 仍由板级驱动清空硬件 FIFO并写入 8 KiB 软件环，但 `tty-reader` 使用单独的低延迟
Waker：同核唤醒请求立即抢占，跨核唤醒通过合并 IPI 请求目标 CPU 调度。普通 Future 保持原有
唤醒策略，避免把串口的低延迟要求扩散到所有异步任务。

正常 TTY 写和完整日志记录共用上层记录锁。板级 UART 锁只覆盖一个物理字符，锁释放后才发送
下一个字符，因此 RX IRQ 可以在字符边界运行。终端生成的回显使用独立的高优先级写入口，允许
在普通输出的字符边界插入；普通写仍保持记录顺序。记录锁持有期间只禁止任务抢占，不关闭 IRQ，
因而锁所有者不会迁核，RX 也不会被整条记录阻塞。一次最多 80 字节的输入回显先在栈上合并，
再执行一次写调用，换行、退格、`ECHOCTL` 和 Ctrl-C 语义不变。

日志锁只在更新所有权元数据时短暂关闭 IRQ。同 CPU 的 IRQ 使用被中断任务的身份重入日志输出；
其他 CPU 的竞争者在 IRQ 开启状态下等待，既避免等待被中断任务而死锁，也不阻塞串口 RX IRQ。

## 3. 构建与静态验证

```bash
make kernel-vf2
make kernel-la-2k1000
```

两个命令分别生成 `moss-vf2.bin` 和 `moss-2k1000la.bin`。构建通过只能证明两套架构和 feature
组合可编译，不能代替串口实测。

测试脚本本身可先做语法检查：

```bash
python3 -m py_compile scripts/test_board_console_latency.py
```

## 4. 实板延迟与粘贴验收

先用对应镜像启动到可交互的 MOSS shell，并退出占用串口的 minicom。VF2 默认执行：

```bash
python3 scripts/test_board_console_latency.py \
  --serial /dev/ttyACM0 \
  --log /tmp/moss-vf2-console-latency.log \
  --json /tmp/moss-vf2-console-latency.json
```

LS2K1000LA 默认执行：

```bash
python3 scripts/test_board_console_latency.py \
  --serial /dev/ttyUSB0 \
  --log /tmp/moss-ls2k1000la-console-latency.log \
  --json /tmp/moss-ls2k1000la-console-latency.json
```

脚本执行以下生产路径检查：

- 空闲 shell 下发送 100 个单键并测量收到回显的时间；
- `busybox yes X` 持续占用串口输出时重复测量，再用 Ctrl-C 恢复 shell；
- 分别粘贴 22、262、518 字节，并由板上 `busybox sha256sum` 校验完整性和顺序。

默认通过标准如下：

| 场景 | P95 | 最大值 |
| --- | ---: | ---: |
| 空闲单键回显 | ≤ 20 ms | ≤ 50 ms |
| 持续输出期间回显 | ≤ 30 ms | ≤ 100 ms |

脚本任何超限、等待超时、粘贴哈希不匹配或串口异常都会以非零状态退出。原始串口日志用于判断
异常发生在 RX、回显、命令投递还是 shell 执行阶段，JSON 文件用于保存可比较的指标。

## 5. 当前验证状态

截至 2026-08-13，VF2、LS2K1000LA 及两套 QEMU release 镜像均已在宿主机完成构建，仓库
自带的 `check_vf2_gmac_static.sh`、`check_ls2k1000_static.sh` 均通过，测试脚本也通过 Python
语法和参数入口检查。本轮不连接目标板，不执行串口自动测试；主机上其他串口设备不属于本次
验收范围。因此表中的延迟阈值和粘贴测试仍属于待实板执行项，不能写成已通过。
