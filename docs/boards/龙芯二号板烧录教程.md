# 龙芯二号板镜像部署与烧录教程

更新日期：2026-08-14

本文记录龙芯 2K1000LA 星云板当前可重复使用的 MOSS 内核部署和 SATA rootfs 烧录方法。这里有三条必须分开的路径：

1. MOSS 内核通过 TFTP 装入 RAM，本身不写 SATA 或 SPI；
2. rootfs 镜像只写 SATA 的 `sda2` 或 `sda3` 分区；
3. 当前不烧写板载 SPI，保留原厂 U-Boot 作为恢复入口。

## 1. 当前磁盘与启动基线

板上的 32 GB SATA 盘当前用途如下：

| 板端设备 | 容量 | 用途 | 是否允许覆盖 |
| --- | ---: | --- | --- |
| `/dev/sda1` | 约 11.8 GiB | 原厂 Linux、旧内核和 2 GiB `/swapfile-moss` | 禁止 |
| `/dev/sda2` | 严格 12 GiB | 原 MOSS/glibc 比赛环境 | 按需烧录 |
| `/dev/sda3` | 严格 6 GiB | LoongArch64 Alpine 现场赛环境 | 按需烧录 |

SATA 盘通过 USB 转接器连接 PC 后，可能变成 `/dev/sdb`、`/dev/sdc` 等设备。板端 `/dev/sda2` 与 PC 端 `/dev/sdb2` 只是在各自系统中的名称，不能假定每次都相同。

> 绝对不要把分区镜像写到 `/dev/sdb` 整盘。这样会覆盖 MBR、原厂 Linux 和全部三个分区。

## 2. 构建并部署 MOSS 内核

生产镜像会自动运行比赛脚本：

```bash
make kernel-la-2k1000
sudo install -o tftp -g tftp -m 0644 \
  moss-2k1000la.bin /srv/tftp/moss-current.bin
sha256sum moss-2k1000la.bin /srv/tftp/moss-current.bin
```

交互镜像进入 BusyBox shell：

```bash
make kernel-la-2k1000-shell
sudo install -o tftp -g tftp -m 0644 \
  moss-2k1000la-shell.bin /srv/tftp/moss-shell.bin
sha256sum moss-2k1000la-shell.bin /srv/tftp/moss-shell.bin
```

`install` 同时复制文件、设置 `tftp:tftp` 所有者和 `0644` 权限。两行 SHA-256 必须相同，才能确认 TFTP 目录中的文件就是刚构建的镜像。

部署到 `/srv/tftp` 不等于写入板载 flash。U-Boot 每次通过网络把镜像装入 RAM，复位后仍回到原厂启动链。

## 3. 自动从 TFTP 启动

生产镜像使用第二分区：

```bash
python3 scripts/run_ls2k1000_serial_tftp.py moss-current.bin \
  --root-device /dev/sda2 \
  --monitor-seconds 180 \
  --log tmp/moss-ls2k1000la.log
```

交互镜像使用第三分区：

```bash
python3 scripts/run_ls2k1000_serial_tftp.py moss-shell.bin \
  --root-device /dev/sda3 \
  --monitor-seconds 180 \
  --log tmp/moss-ls2k1000la-shell.log
```

脚本操作 `/dev/ttyUSB0`，从原厂 Linux 安全卸载目标分区，拦截 U-Boot、设置 DT、加载镜像并执行。`--root-device` 只接受 `/dev/sda2` 或 `/dev/sda3`；建议每次显式写出，避免使用错根分区。

## 4. 手工从 U-Boot 启动

进入 U-Boot 后，下面的示例从第三分区启动交互镜像：

```text
setenv ipaddr 192.168.88.2
setenv serverip 192.168.88.1
setenv netmask 255.255.255.0
setenv ethact ethernet@40040000

tftpboot 0x900000000a000000 board.dtb
fdt addr 0x900000000a000000
fdt resize 4096
fdt set /chosen bootargs root=/dev/sda3
fdt set /aliases ethernet0 /2k1000-soc/ethernet@40040000
fdt set /2k1000-soc/ahci@400e0000 ports-implemented <0x1>

tftpboot 0x9000000098000000 moss-shell.bin
go 0x9000000098000040 0x900000000a000000
```

启动 `moss-current.bin` 时通常把根分区改为 `/dev/sda2`。这些命令只修改本次 RAM 中的环境和 DT，不需要执行 `saveenv`。

`/srv/tftp/board.dtb` 是当前板上验证过的 DTB。它不在仓库构建流程中自动生成，替换前应先另存备份并校验哈希。

## 5. 烧录 SATA 前识别设备

关闭开发板电源，取下 SATA 盘并通过 SATA-USB 转接器连接 PC。先执行：

```bash
lsblk -b -o NAME,PATH,SIZE,MODEL,SERIAL,TRAN,RM,TYPE,FSTYPE,MOUNTPOINTS
sudo fdisk -l /dev/sdb
```

以下命令以确认后的 SATA 盘为 `/dev/sdb` 为例。必须同时核对总容量、型号、序列号和三个分区，不能只看设备名。

烧录前检查目标分区是否挂载：

```bash
findmnt --source /dev/sdb2
findmnt --source /dev/sdb3
```

目标有挂载时，只卸载将要烧录的那个分区。例如：

```bash
sudo umount /dev/sdb3
```

不要卸载或修改无关磁盘，也不要重新分区。当前教程只覆盖已经存在的 `sda2`、`sda3`。

## 6. 将 12 GiB MOSS 环境写入第二分区

当前已全量校验的第二分区镜像为：

```text
/srv/tftp/sdcard-la-clean-12g-20260811.img
size   = 12,884,901,888 bytes
sha256 = 35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d
```

先验证源文件：

```bash
stat -c '%n %s bytes' /srv/tftp/sdcard-la-clean-12g-20260811.img
sha256sum /srv/tftp/sdcard-la-clean-12g-20260811.img
sudo e2fsck -f -n /srv/tftp/sdcard-la-clean-12g-20260811.img
```

确认 PC 上的第二分区也是严格 12 GiB 后写入：

```bash
sudo dd if=/srv/tftp/sdcard-la-clean-12g-20260811.img \
  of=/dev/sdb2 bs=16M iflag=fullblock oflag=direct \
  status=progress conv=fsync
```

该镜像已经是 12 GiB，不需要再执行 `resize2fs`。从整分区读回并全量验证：

```bash
sudo dd if=/dev/sdb2 bs=16M iflag=fullblock status=progress | sha256sum
sudo e2fsck -f -n /dev/sdb2
```

读回摘要必须仍为 `35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d`。

## 7. 将 Alpine 环境写入第三分区

当前 TFTP 目录中的工作镜像已经执行过 ext4 修复并通过只读检查：

```text
/srv/tftp/alpine-linux-loongarch64.img
size   = 723,517,440 bytes（690 MiB）
sha256 = 0ad295fc3e62dad2dd15ccf575135bc8c17fe8cddb510f3aa9ff44c4e1be2173
uuid   = a4aa5d0b-8116-474e-919d-b73f9641db05
```

写入前验证：

```bash
sha256sum /srv/tftp/alpine-linux-loongarch64.img
sudo e2fsck -f -n /srv/tftp/alpine-linux-loongarch64.img
```

写入第三分区：

```bash
sudo dd if=/srv/tftp/alpine-linux-loongarch64.img \
  of=/dev/sdb3 bs=16M iflag=fullblock oflag=direct \
  status=progress conv=fsync
```

先从目标分区读回原镜像覆盖的 690 MiB，并核对哈希：

```bash
sudo dd if=/dev/sdb3 bs=1M count=690 iflag=fullblock status=progress | sha256sum
```

摘要一致后修复并扩展到整个 6 GiB 分区：

```bash
sudo e2fsck -f -y /dev/sdb3
sudo resize2fs /dev/sdb3
sudo e2fsck -f -n /dev/sdb3
```

原始下载文件 `/home/wuxun/Downloads/alpine-linux-loongarch64-ext4fs.img.xz` 的压缩数据也已通过 `xz -t`；它解压后同为 723,517,440 字节。原始解压数据的 SHA-256 是 `57c64d68d12aed1e503cc54753ea27f8c38936d6dde78d7c28dfc155763e25ca`。它与 `/srv/tftp` 工作镜像哈希不同，是因为工作镜像已经执行过 ext4 一致性修复；烧录时应选定其中一个来源，不要把两个哈希混用。

## 8. 完成检查和安全断电

检查分区表和文件系统：

```bash
sudo fdisk -l /dev/sdb
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS /dev/sdb
sudo blkid /dev/sdb1 /dev/sdb2 /dev/sdb3
sudo e2fsck -f -n /dev/sdb2
sudo e2fsck -f -n /dev/sdb3
```

确认检查通过且没有分区挂载后执行：

```bash
sync
udisksctl power-off -b /dev/sdb
```

设备从 `lsblk` 消失后再拔出转接器并把 SATA 盘装回开发板。

## 9. SPI 固件保护边界

当前生产流程不执行 SPI erase/write。原厂 U-Boot、环境、bdinfo 和 DTB 的只读备份位于 `/srv/tftp`，可在仓库根目录验证：

```bash
sha256sum -c docs/ls2k1000la-spi-backup-20260809.sha256
```

`u-boot-with-spl.bin` 只完成过候选构建和 RAM-chain 验证，尚未证明与本板原厂 DDR 参数及恢复流程逐字等价。不要将候选 U-Boot 写入 SPI。当前 TFTP+RAM 方案已经满足 MOSS 启动需求，并保留原厂固件作为可靠恢复入口。

日常构建和上板入口见 [龙芯二号板当前使用指南](龙芯二号板当前使用指南.md)，历史分区与 SPI 验证依据见 [龙芯二号板调试状态报告](龙芯二号板调试状态报告-20260808.md)。
