# 龙芯二号板通过原厂 Linux 网络烧录镜像

更新日期：2026-08-19

本文只记录一件事：没有 SATA-USB 转接器时，把 PC 上的 rootfs 镜像通过网络传给龙芯
2K1000LA 板上的原厂 Linux，并直接写入 SATA 的 `sda2` 或 `sda3`。

数据路径是：

```text
PC 镜像 -> /srv/tftp -> 临时 HTTP -> 原厂 Linux wget -> /dev/sda2 或 /dev/sda3
```

整个过程不把镜像保存到 `sda1`，因此不会额外占用原厂 Linux 根分区的空间。

实际执行时只需选一条路径：

- 烧录 Alpine 到 `sda3`：按第 2、3、4、6 节执行；
- 烧录 MOSS/Debian 到 `sda2`：按第 2、3、5、6 节执行。

## 1. 烧录前必须知道的边界

当前 SATA 分区用途如下：

| 分区 | 容量 | 用途 | 是否允许覆盖 |
| --- | ---: | --- | --- |
| `/dev/sda1` | 约 11.8 GiB | 原厂 Linux、旧内核、swapfile | 禁止 |
| `/dev/sda2` | 严格 12 GiB | MOSS/Debian glibc 环境 | 按需烧录 |
| `/dev/sda3` | 严格 6 GiB | LoongArch64 Alpine 环境 | 按需烧录 |

只允许写具体分区：

```text
/dev/sda2
/dev/sda3
```

> 绝对不得写 `/dev/sda` 整盘，否则会覆盖 MBR、原厂 Linux 和全部分区。

本文不改分区表、不合并或拆分分区、不写 SPI，也不执行 `saveenv`。

## 2. PC 端：把镜像复制到网络目录

PC 上的网络文件目录是：

```text
/srv/tftp
```

必须使用已解压的 `.img` 文件，不要把 `.xz` 压缩包直接写入 SATA 分区。

### 2.1 复制镜像

假设要烧录的镜像位于 `/home/wuxun/Downloads/rootfs.img`，执行：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
stat -c '%n %s bytes' \
  /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
sha256sum \
  /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
```

第一条命令只删除上一次使用的统一临时副本 `/srv/tftp/rootfs.img`，不会删除
`/home/wuxun/Downloads` 中真正的源镜像。每次复制新镜像前都执行，避免误用旧镜像。

只需把第二条 `cp` 命令中的源路径换成实际镜像路径。目标文件统一叫做
`/srv/tftp/rootfs.img`，后面的板端命令就不需要再改文件名。`stat` 显示的两个字节数和
`sha256sum` 显示的两个哈希必须分别相同，否则不启动 HTTP、不写盘。

如果要烧录当前已验证的镜像，它们已经在 `/srv/tftp` 中，可以不再复制：

| 目标 | PC 上的镜像 | 字节数 | SHA-256 |
| --- | --- | ---: | --- |
| `sda2` | `/srv/tftp/sdcard-la-clean-12g-20260811.img` | 12,884,901,888 | `35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d` |
| `sda3` | `/srv/tftp/alpine-linux-loongarch64.img` | 723,517,440（690 MiB） | `0ad295fc3e62dad2dd15ccf575135bc8c17fe8cddb510f3aa9ff44c4e1be2173` |

使用这两个现有镜像时，先把要烧录的那一个复制为统一文件名。例如烧录 Alpine：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /srv/tftp/alpine-linux-loongarch64.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
```

烧录 12 GiB MOSS/Debian 镜像时：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /srv/tftp/sdcard-la-clean-12g-20260811.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
```

### 2.2 记录源镜像的大小和哈希

```bash
stat -c '%n %s bytes' /srv/tftp/rootfs.img
sha256sum /srv/tftp/rootfs.img
```

把输出的字节数和 SHA-256 保留好。写盘后必须从板端分区读回同样多的字节，得到相同
SHA-256，才算烧录成功。

### 2.3 配置 PC 网口并启动 HTTP

当前连接龙芯板的 PC 网口是 `enp3s0`：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
ip -brief address show enp3s0
```

在 PC 的一个单独终端中启动 HTTP：

```bash
python3 -m http.server 8000 \
  --bind 192.168.88.1 \
  --directory /srv/tftp
```

保持这个终端运行。再打开另一个 PC 终端检查：

```bash
curl -I http://192.168.88.1:8000/rootfs.img
```

必须看到 `HTTP/1.0 200 OK` 和正确的 `Content-Length`。

## 3. 板端：进入原厂 Linux 并确认目标

烧录必须在板上原厂 Linux 中执行，不要在当前以 `sda2` 或 `sda3` 为根的 MOSS 中执行。

先检查磁盘和挂载点：

```bash
findmnt /
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/sda
```

必须确认：

- 原厂 Linux 的 `/` 在 `sda1`；
- 本次要写的 `sda2` 或 `sda3` 不是当前根分区。

配置板端网络：

```bash
ip link set eth0 up
ip address replace 192.168.88.2/24 dev eth0
ping -c 3 192.168.88.1
busybox wget -O /dev/null http://192.168.88.1:8000/board.dtb
```

`ping` 必须 0% 丢包，`wget` 必须成功。这里不需要公网、DNS、NAT 或 NTP，只使用 PC 和板卡
之间的直连网络。

## 4. 烧录 `sda3`（6 GiB Alpine）

只有要写 `sda3` 时才执行本节。

### 4.1 写盘前确认尺寸和卸载

```bash
cat /sys/class/block/sda3/size
```

必须输出：

```text
12582912
```

该数字乘以 512 bytes 就是严格 6 GiB。然后执行：

```bash
umount /dev/sda3 2>/dev/null || true
sync
findmnt -rn -S /dev/sda3
```

`findmnt` 必须没有任何输出。`umount` 的错误被隐藏，是因为分区本来就可能没有挂载；最后的
`findmnt` 才是必须通过的安全检查。

### 4.2 通过网络直接写入

```bash
busybox wget -O /dev/sda3 http://192.168.88.1:8000/rootfs.img
echo "wget_rc=$?"
sync
```

必须看到：

```text
wget_rc=0
```

如果断网、重启或 `wget_rc` 不是 0，此时分区内容不完整，不要挂载或启动。修复网络后重新执行
同一条 `wget -O /dev/sda3 ...` 从头覆盖即可。

### 4.3 读回哈希并扩展 ext4

当前 Alpine 镜像是精确 690 MiB，执行：

```bash
dd if=/dev/sda3 bs=1M count=690 iflag=fullblock | sha256sum
```

必须得到：

```text
0ad295fc3e62dad2dd15ccf575135bc8c17fe8cddb510f3aa9ff44c4e1be2173
```

只有哈希一致后，才执行：

```bash
e2fsck -f -y /dev/sda3
resize2fs /dev/sda3
e2fsck -f -n /dev/sda3
```

最后一条 `e2fsck` 必须完成五个检查阶段且没有文件系统错误。

## 5. 烧录 `sda2`（12 GiB MOSS/Debian）

只有要写 `sda2` 时才执行本节。

### 5.1 写盘前确认尺寸和卸载

```bash
cat /sys/class/block/sda2/size
```

必须输出：

```text
25165824
```

该数字乘以 512 bytes 就是严格 12 GiB。然后执行：

```bash
umount /dev/sda2 2>/dev/null || true
sync
findmnt -rn -S /dev/sda2
```

`findmnt` 必须没有任何输出。

### 5.2 通过网络直接写入

```bash
busybox wget -O /dev/sda2 http://192.168.88.1:8000/rootfs.img
echo "wget_rc=$?"
sync
```

必须看到 `wget_rc=0`。当前 12 GiB 镜像与分区等大，不执行 `resize2fs`。

### 5.3 整分区读回验证

```bash
dd if=/dev/sda2 bs=16M iflag=fullblock | sha256sum
```

必须得到：

```text
35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d
```

然后执行只读文件系统检查：

```bash
e2fsck -f -n /dev/sda2
```

## 6. 完成、关机和启动

无论写 `sda2` 还是 `sda3`，最后都执行：

```bash
sync
lsblk -o NAME,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINTS /dev/sda
```

需要关机时：

```bash
poweroff
```

完全关机后再断电。PC 上的 HTTP 终端按 `Ctrl+C` 停止服务。

镜像烧录完成后，MOSS 内核仍由 U-Boot 通过 TFTP 加载到 RAM，并在 bootargs 中选择
`root=/dev/sda2` 或 `root=/dev/sda3`。启动命令见
[龙芯二号板当前使用指南](龙芯二号板当前使用指南.md)。

## 7. 最简验收标准

只要同时满足下面四项，就可以判定烧录成功：

1. PC 上 `curl -I` 返回 `200 OK` 和正确的 `Content-Length`；
2. 板端写入前 `findmnt` 没有显示目标分区被挂载；
3. `wget_rc=0`，且从块设备读回的 SHA-256 与 PC 源镜像一致；
4. 目标分区的 `e2fsck -f -n` 检查通过。

其中任意一项不满足，都不要启动该分区。
