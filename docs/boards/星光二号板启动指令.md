# VisionFive 2 上板常用指令

本文记录在 VisionFive 2 上构建、传输和启动 Moss 的常用操作。以下命令按当前测试环境编写，设备名变化时请相应替换。

GMAC1 的驱动架构、DMA/PHY/中断实现和分层验收依据见 [VisionFive 2 GMAC1 驱动实现与验收](星光二号板网卡驱动实现与验收.md)。

| 项目 | 当前配置 |
| --- | --- |
| 串口 | `/dev/ttyACM0`，115200 波特率 |
| PC 网口 | `enp108s0` |
| PC IP | `192.168.1.2` |
| 板端 U-Boot IP | `192.168.1.10` |
| TFTP 目录 | `/srv/tftp` |
| SD 卡 | PC 端通常为 `/dev/sdb`，U-Boot 中为 `mmc 1` |
| 内核加载地址 | `0x40200000` |

> 写卡前必须用 `lsblk` 再次确认 SD 卡设备，避免覆盖 PC 磁盘。

## 1. 接线

- USB 串口连接 PC，用于查看日志和输入命令。
- 网线直连 PC 与开发板，用于 U-Boot TFTP 传输内核和 Moss 网络通信。
- 插入写有 Moss rootfs 的 SD 卡。

## 2. 构建内核

在 Moss 仓库根目录执行：

```bash
make kernel-vf2
```

生成文件：

```text
moss-vf2.bin
```

VF2 上的功能测试统一使用该内核。`scripts/run_rv.sh` 用于 PC 上启动 QEMU，不用于 VF2 实板。

提交前可运行 GMAC1 静态检查。它会验证主线 Linux 与 StarFive U-Boot 2021.10 两种 DT 格式、运行状态机，并重新构建 VF2 镜像：

```bash
scripts/check_vf2_gmac_static.sh
```

## 3. 配置网络和 TFTP

配置 PC 网口：

```bash
sudo ip addr replace 192.168.1.2/24 dev enp108s0
sudo ip link set enp108s0 up
ip addr show enp108s0
```

复制待启动内核：

```bash
sudo cp moss-vf2.bin /srv/tftp/kernel
```

查看 TFTP 服务：

```bash
ps -ef | grep '[i]n.tftpd'
```

若服务尚未运行：

```bash
sudo /usr/sbin/in.tftpd --listen --user tftp \
  --address 192.168.1.2:69 --secure /srv/tftp
```

## 4. 准备 SD 卡 rootfs

当前 SD 卡使用 GPT 多分区布局，不能再把 rootfs 镜像写到 `/dev/sdb` 整盘，否则会覆盖分区表及其他系统。当前分区用途为：

| Moss 中的名称 | 当前用途 | 实测容量 |
| --- | --- | --- |
| `/dev/sda1` | Debian Linux | 29.8 GiB |
| `/dev/sda2` | Moss rootfs | 29.8 GiB |
| `/dev/sda3` | Alpine Linux 比赛环境 | 27.9 GiB |
| `/dev/sda4` | 空白比赛分区 | 27.9 GiB |
| `/dev/sda5` | swap | 3.7 GiB |

镜像必须写入具体分区，例如 PC 上的 `/dev/sdb2`、`/dev/sdb3` 或 `/dev/sdb4`。设备识别、压缩镜像写入、哈希校验、扩容和安全断电的完整步骤见 [星光二号板分区镜像烧录教程](星光二号板分区镜像烧录教程.md)。

## 5. 打开串口和进入 U-Boot

在 PC 上启动 minicom：

```bash
sudo minicom -D /dev/ttyACM0 -b 115200 -o
```

常用按键：

- `Ctrl-A` 后按 `Z`：查看帮助。
- `Ctrl-A` 后按 `X`：退出 minicom。
- 开发板复位或上电后，在倒计时期间按任意键：进入 U-Boot。
- 若已开始自动网络启动，按 `Ctrl-C`，直到出现 `StarFive #`。

进入 MOSS 后如需量化单键回显、持续输出竞争和长粘贴完整性，关闭 minicom 后运行
[VF2 与 LS2K1000LA 串口输入延迟修复和验收](双板串口输入延迟修复与验收.md)中的通用脚本。

## 6. 通过 TFTP 加载并启动 Moss

在 `StarFive #` 下执行：

```text
setenv ipaddr 192.168.1.10
setenv serverip 192.168.1.2
fdt addr 0x42200000
fdt resize 4096
fdt set /chosen bootargs root=/dev/sda2
tftpboot 0x40200000 kernel
go 0x40200000
```

`root=/dev/sda2` 让 Moss 挂载第二分区。需要使用 Alpine 比赛环境时改为
`root=/dev/sda3`；第四分区写入 rootfs 后可改为 `root=/dev/sda4`。`/dev/sda5` 是 swap，
不能作为根分区。这里的 `/dev/sdaN` 是 Moss 的逻辑命名，不受 SD 卡插到 PC 后显示为
`/dev/sdbN` 或 `/dev/sdcN` 影响。这些设置只对本次启动有效，不需要执行 `saveenv`。

## 7. 在 U-Boot 中查看 SD 卡

选择并检测 SD 卡：

```text
mmc dev 1
mmc rescan
mmc info
```

查看 GPT 分区表，并检查各 rootfs：

```text
part list mmc 1
fstype mmc 1:1
ls mmc 1:1 /
fstype mmc 1:2
ls mmc 1:2 /
fstype mmc 1:3
ls mmc 1:3 /
```

第四分区当前为空，因此在写入文件系统前，下面的 `fstype` 失败是正常现象：

```text
fstype mmc 1:4
```

其中 `mmc 1:2` 对应 Moss 的 `/dev/sda2`，`mmc 1:3` 对应 `/dev/sda3`。

## 8. 在 PC 上查看或复制 SD 卡文件

SD 卡插回 PC 后先重新确认设备名：

```bash
lsblk -o NAME,PATH,SIZE,MODEL,TRAN,FSTYPE,MOUNTPOINTS
```

以下以第二分区实际显示为 `/dev/sdb2` 为例：

```bash
sudo mkdir -p /mnt/moss-sd
sudo mount /dev/sdb2 /mnt/moss-sd
ls /mnt/moss-sd
sudo cp <本地文件> /mnt/moss-sd/<目标路径>
sync
sudo umount /mnt/moss-sd
```

查看第一、第三或第四分区时，必须将 `/dev/sdb2` 换成 `lsblk` 实际确认到的具体分区。不要挂载或写入 `/dev/sdb` 整盘。

## 9. Moss 启动后的常用检查

```sh
ls /
ls /glibc
cat /proc/cpuinfo
cat /proc/meminfo
cat /sys/devices/system/cpu/online
nproc
mount
```

当前 VF2 使用 4 个 U74 核，后两条命令应分别输出 `0-3` 和 `4`。

在 Moss Shell 中运行 cagent：

```sh
cd /glibc
./cagent_testcode.sh
```

运行 buildstorm：

```sh
cd /glibc
./buildstorm_testcode.sh
```

验证 Moss 向 PC 发送 TCP 数据，先在 PC 执行：

```bash
nc -l 192.168.1.2 19000
```

再在 Moss 中执行：

```sh
echo MOSS_VF2_TX_OK | busybox nc -w 3 192.168.1.2 19000
```

验证 PC 向 Moss 发送数据，先在 Moss 中执行：

```sh
busybox nc -l -p 19001
```

再在 PC 执行：

```bash
printf 'MOSS_VF2_RX_OK\n' | nc -w 3 192.168.1.10 19001
```

### 自动化 GMAC1 验收

关闭占用 `/dev/ttyACM0` 的 minicom 后，可由脚本完成临时 U-Boot 配置、TFTP 启动、双向 64 KiB TCP 哈希校验和断链恢复测试：

```bash
sudo scripts/run_vf2_gmac_test.py \
  --serial /dev/ttyACM0 \
  --interface enp108s0 \
  --log vf2-gmac.log
```

脚本启动后再复位开发板。它不执行 `saveenv`；退出时会恢复 PC 网口的管理状态、测速修改过的 ethtool 参数和原有 TFTP 目标文件。若还要覆盖 1000/100/10 Mbps 重协商：

```bash
sudo scripts/run_vf2_gmac_test.py --speed-suite --log vf2-gmac-speed.log
```

若 rootfs 已配置 Alpine 仓库、DNS 和 CA 证书，可额外测试拉取软件包：

```bash
sudo scripts/run_vf2_gmac_test.py \
  --apk-package busybox \
  --log vf2-gmac-apk.log
```

该选项依次检查 ICMP、双向 TCP、DNS、TLS、`apk update` 和 `apk fetch`，并确认目标目录中确实生成 `.apk` 文件，因此 APK 失败时可以区分是网卡、域名解析、证书/TLS 还是仓库/包的问题。

## 10. 常见问题

- `Card did not respond to voltage select! : -110` 通常来自未就绪的 `mmc 0`；SD 卡应使用 `mmc 1`。
- `serverip not set`：重新执行 `setenv serverip 192.168.1.2`。
- 一个网口 PHY 超时不代表 TFTP 一定失败；成功时通常会切换到 `ethernet@16040000`。
- `tftpboot` 失败时检查网线、PC 网口 IP、TFTP 服务和 `/srv/tftp/kernel`。
- Moss 已支持 VF2 物理网口的 TCP/IP 通信；`scp` 仍取决于 rootfs 是否提供 SSH 客户端或服务端。更新内核建议继续使用 U-Boot TFTP。
- MOSS 只接管 PHY 运行期的链路、速率、双工、流控和 YT8531 TX 时钟相位；上电后的 RX/TX delay 与驱动强度仍由 U-Boot 初始化。因此不要跳过 VF2 v1.3B 的正常固件启动链直接进入 MOSS。
- 当前驱动仅支持 VF2 v1.3B 的 GMAC1 `rgmii-id`。v1.2A 的 GMAC1 为 RMII 接线，驱动会明确拒绝该模式。
