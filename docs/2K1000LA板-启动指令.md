# 龙芯 2K1000LA 上板常用指令

本文记录龙芯 2K1000LA 星云版上构建、传输和启动 MOSS 的常用操作。
基本流程和 VisionFive 2 相同：通过串口进入 U-Boot，用 TFTP 把 MOSS 内核加载到内存，
然后启动内核。

2K1000LA 的主要区别是：

- rootfs 位于板载 SATA 硬盘，而不是 SD 卡。
- MOSS 启动时需要 U-Boot 把 DTB 的内存地址传给内核。
- DTB 可以直接复用原厂 U-Boot 已经加载的板载设备树，不需要每次从 PC 下载。

| 项目 | 当前配置 |
| --- | --- |
| 串口 | `/dev/ttyUSB0`，115200 8N1 |
| PC 有线网卡 | `enp108s0` |
| PC IP | `192.168.88.1` |
| 板卡 IP | `192.168.88.2` |
| TFTP 目录 | `/srv/tftp` |
| MOSS 加载地址 | `0x9000000098000000` |
| MOSS 入口地址 | `0x9000000098000040` |
| DTB 工作副本地址 | `0x900000000a000000` |

> 本文中的 `setenv` 只影响当次启动。不要执行 `saveenv`，不要擦写 SPI，
> 也不会覆盖板子原有的 Linux。

## 1. 板子当前的系统和硬盘

板子保留原厂 U-Boot 和 Linux。默认启动流程是：

```text
SPI 中的 U-Boot -> SATA 硬盘上的原厂 Linux
```

当我们手工进入 U-Boot 启动 MOSS 时：

```text
SPI 中的 U-Boot -> TFTP 加载 MOSS 到内存 -> MOSS 使用 SATA 上的 rootfs
```

当前 SATA 硬盘的主要分区为：

| 分区 | 内容 | 用途 |
| --- | --- | --- |
| `/dev/sda1` | 原厂 Linux | 板子默认启动的系统，保留不动 |
| `/dev/sda2` | MOSS/glibc 比赛环境 | 用于 cagent 和 buildstorm |
| `/dev/sda3` | Alpine LoongArch64 环境 | 包含 Git、Vim、GCC 和 rustc，适合现场手工操作 |

MOSS 内核通过 TFTP 临时进入内存，不会写入 SPI。重启后如果不再截停 U-Boot，
板子仍会返回原厂 Linux。

## 2. 接线

- USB 串口连接 PC，用于查看 U-Boot 和 MOSS 日志。
- 网线直连 PC 与 2K1000LA，用于 TFTP 传输 MOSS 内核。
- 保持板载 SATA 硬盘连接稳定。

当前串口设备为：

```bash
ls -l /dev/ttyUSB0
```

## 3. 构建 MOSS

首次上板建议使用交互镜像：

```bash
cd /home/wuxun/Projects/moss-dev
make site-2kla
```

生成文件：

```text
build/site-2kla/moss-2kla.bin
```

该镜像按 2 核、2 GiB 构建，启动后进入 BusyBox shell，适合手工执行命令。龙芯不再生成自动执行版。

## 4. 配置 PC 网口和 TFTP

当前直连板卡的 PC 网口是 `enp108s0`。从 VF2 切换到 2K1000LA 时，把 PC IP 从
`192.168.1.2` 改成 `192.168.88.1`：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp108s0
sudo ip link set enp108s0 up
ip addr show enp108s0
```

复制镜像到 TFTP 目录：

```bash
sudo cp build/site-2kla/moss-2kla.bin /srv/tftp/moss-2kla.bin
```


检查 TFTP 服务：

```bash
ps -ef | grep '[i]n.tftpd'
```

如果服务未运行：

```bash
sudo /usr/sbin/in.tftpd --listen --user tftp \
  --address 192.168.88.1:69 --secure /srv/tftp
```

## 5. 打开串口并进入 U-Boot

打开 picocom：

```bash
picocom -b 115200 /dev/ttyUSB0

```

常用按键：

- `Ctrl-A` 后按 `Ctrl + X`：退出 picocom。
- 在 MOSS shell 中按 `Ctrl-C`：中断当前前台程序。

2K1000LA 的原厂 U-Boot 自动启动很快，而且会清空很早的串口输入。复位或上电后，
连续按 `c`，直到出现：

```text
=>
```

不要执行 `saveenv`。

## 6. 使用已验证的实板 DTB

DTB 由 MOSS 内核读取和解析，但 U-Boot 需要先把 DTB 放在内存中，并在启动内核时
传入它的地址。

历史真机验收使用的是 TFTP 目录中单独保存的 `board.dtb`，不是
U-Boot 的 `fdtcontroladdr` control DTB。在 PC 上先确认文件存在：

```bash
test -s /srv/tftp/board.dtb && ls -l /srv/tftp/board.dtb
```

如果该文件不存在，不要改用 `fdtcontroladdr`。两份 DTB 的内存布局和节点结构
不同，control DTB 不能用于当前 MOSS 启动。

## 7. 加载并启动 MOSS

先在 U-Boot `=>` 下设置网络，下载实板 DTB，再补齐 MOSS 当前需要的
网卡和 AHCI 设备树属性：

```text
setenv ipaddr 192.168.88.2
setenv serverip 192.168.88.1
setenv netmask 255.255.255.0
setenv ethact ethernet@40040000

tftpboot 0x900000000a000000 board.dtb
fdt addr 0x900000000a000000
fdt resize 4096

fdt set /aliases ethernet0 /2k1000-soc/ethernet@40040000
fdt set /2k1000-soc/ahci@400e0000 ports-implemented <0x1>

fdt print /aliases ethernet0
fdt print /2k1000-soc/ahci@400e0000 ports-implemented
```

### 7.1 启动交互环境 `/dev/sda3`

```text
fdt set /chosen bootargs root=/dev/sda3

tftpboot 0x9000000098000000 moss-2kla.bin
go 0x9000000098000040 0x900000000a000000
```

启动后应进入：

```text
starry:~#
```

### 7.2 启动 `/dev/sda2` 上的 cagent/buildstorm 环境

如果使用交互镜像手动运行测试：

```text
fdt set /chosen bootargs root=/dev/sda2
tftpboot 0x9000000098000000 moss-2kla.bin
go 0x9000000098000040 0x900000000a000000
```

## 8. MOSS 启动后的常用检查

```sh
uname -m
nproc
cat /sys/devices/system/cpu/online
cat /proc/cpuinfo
cat /proc/meminfo
free -h
mount
df -h /
ip addr
```

当前目标配置是 2 核、2 GiB 内存：

- `uname -m` 应为 `loongarch64`。
- `nproc` 应为 `2`。
- CPU online 应为 `0-1`。

U-Boot banner 中的 `2G-factory` 不是真实内存容量，当前板子的实际基线是 1 GiB。

## 9. 运行比赛脚本

在使用 `/dev/sda2` 启动的交互 shell 中：

```sh
cd /glibc
bash ./cagent_testcode.sh
```

```sh
cd /glibc
bash ./buildstorm_testcode.sh
```

`/dev/sda3` 环境中可检查现场工具：

```sh
git --version
vim --version | head
gcc --version | head
rustc --version
```

## 10. PC 和 MOSS 之间传文件

断网时仍可以使用 PC 和板卡之间的直连网络。

在 PC 的文件所在目录执行：

```bash
python3 -m http.server 8000 --bind 192.168.88.1
```

在 MOSS 中执行：

```sh
cd /root
wget http://192.168.88.1:8000/<文件名>
sync
sha256sum <文件名>
```

可以在 PC 和 MOSS 两端分别执行 `sha256sum`，确认文件完整。

## 11. 安全重启

在 MOSS 中执行：

```sh
sync
reboot
```

也可以在交互 init shell 中执行：

```sh
exit
```

内核会先同步并卸载文件系统，然后重启。不要在 MOSS 运行期间直接断电，
也不要使用 `reboot -f`。

## 12. 常见问题

- **进不去 U-Boot**：复位后连续按 `c`，不要只按一次。
- **`board.dtb` 不存在**：先恢复历史真机验证过的备份；不要改用
  `fdtcontroladdr`，也不要把静态测试用 DTS fixture 当成实板 DTB。
- **`tftpboot` 失败**：检查 PC IP、网线、TFTP 进程和 `/srv/tftp/moss-2kla.bin`。
- **MOSS 找不到根分区**：确认 `/chosen/bootargs` 中的 `root=/dev/sda2` 或
  `root=/dev/sda3` 与本次要使用的环境一致。
- **原厂 Linux 已经挂载 sda2/sda3**：在 Linux 中先执行 `umount /dev/sda3`、`sync` 和
  `reboot`，再截停 U-Boot。冷启动时在 Linux 运行前直接截停 U-Boot，则不存在同时挂载问题。
- **断网时显示 NTP 失败**：等待尝试结束，之后仍会进入 `starry:~#`，不影响离线操作。

## 13. 高级自动化（非首次上板必需）

`scripts/run_ls2k1000_serial_tftp.py` 用于自动卸载分区、截停 U-Boot、配置 swap、
输入启动命令和保存长时间日志。普通上板、调试内核和使用 shell 时不需要它。

只有运行完整 buildstorm、需要 1 GiB 板卡上的 swap，或需要反复自动验收时，
再参考 [2K1000LA 当前方案与使用指南](ls2k1000la-current-guide.md)。
