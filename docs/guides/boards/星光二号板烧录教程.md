# 星光二号板：SD 卡分区镜像烧录

本文使用读卡器，在宿主机上把 RISC-V64 比赛 ext4 镜像写入 VisionFive 2 的 SD 卡第三分区，使用的 SD 卡为 128 GB。
从[百度网盘](https://pan.baidu.com/s/1zTb2NPCp9HE_l_M-3-oczg?pwd=kyva)下载镜像 `sdcard-rv-pub.img.gz`，
提取码 `kyva`，放到 `moss/rootfs/` 目录下。下面的宿主机操作从 `moss` 项目根目录开始。

```text
解压镜像 → 确认 SD 卡和目标分区 → 写入 → 全量校验 → 检查并扩容 → 安全拔卡 → VF2 启动
```

烧录会覆盖目标分区的内容，需要保留的文件先备份。保留现有分区表和其他分区，
只写具体分区。命令逐段执行，报错就停止。

## 1. 分区与设备名称

原测试卡的五分区用途和历史实测容量如下；实际设备名和容量以接入宿主机后的查询结果为准。

| 分区 | 宿主机设备示例 | VF2 启动时的设备名 | 历史实测容量 | 用途 |
| --- | --- | --- | --- | --- |
| p1 | `/dev/sdb1` | `/dev/mmcblk1p1` | 29.8 GiB | 原厂 Debian Linux |
| p2 | `/dev/sdb2` | `/dev/mmcblk1p2` | 29.8 GiB | 原有 MOSS 根文件系统，保留不动 |
| p3 | `/dev/sdb3` | `/dev/mmcblk1p3` | 27.9 GiB | MOSS 比赛环境，本教程的烧录和启动分区 |
| p4 | `/dev/sdb4` | `/dev/mmcblk1p4` | 27.9 GiB | 另一个根文件系统分区 |
| p5 | `/dev/sdb5` | `/dev/mmcblk1p5` | 3.7 GiB | swap，保留不动 |

`/dev/sdb` 是整张卡，`/dev/sdb3` 才是第三分区。读卡器重新插拔后设备名可能改变，
确认实际设备后，将下文中的 `/dev/sdb` 和 `/dev/sdb3` 对应替换。

## 2. 宿主机：解压镜像

```bash
cd rootfs
gzip -dc sdcard-rv-pub.img.gz > rv-rootfs.img
```

`cd` 进入镜像目录；`gzip -d` 解压，`-c` 将结果输出到 `rv-rootfs.img`，保留原 `.gz` 文件。
解压需要至少 14 GiB 空闲空间，须正常结束后再继续。这条命令会覆盖已有的 `rv-rootfs.img`；
烧录 VF2 时使用本步从 RV 压缩包解压的副本。后续宿主机操作沿用此终端和目录。

```bash
file rv-rootfs.img
image_bytes=$(stat -c %s rv-rootfs.img)
echo "$image_bytes"
```

`file` 应识别出 ext4 文件系统；带分区表的整盘镜像不适用于本流程。
`stat -c %s` 取得镜像字节数，保存到 `image_bytes` 并显示，供容量比较和写入校验使用。
该镜像解压后的逻辑大小为 14 GiB，具体字节数以 `stat` 输出为准。

## 3. 宿主机：确认 SD 卡并卸载目标分区

先将 VF2 正常关机并断电，再把 SD 卡取出，通过读卡器接入宿主机。

```bash
lsblk -b -o NAME,SIZE,MODEL,TRAN,FSTYPE,MOUNTPOINTS
```

`-b` 以字节显示容量，`-o` 指定设备名、容量、型号、接口、文件系统和挂载点。
结合 SD 卡容量、读卡器型号和 USB 接口确认设备，并确认第三分区容量不小于 `image_bytes`。
下面以确认后的 `/dev/sdb3` 为例：

```bash
sudo umount /dev/sdb3
findmnt -S /dev/sdb3
```

`umount` 卸载目标分区；若只提示未挂载，可继续。若提示忙或其他错误，先处理占用。
`findmnt -S` 查询该设备的挂载记录，无输出且退出码为 `1` 表示未挂载；有输出或报错时停止。
写入、校验和扩容期间保持目标分区未挂载。

## 4. 宿主机：写入第三分区

```bash
sudo dd if=rv-rootfs.img of=/dev/sdb3 bs=16M status=progress conv=fsync
```

`if` 指定镜像，`of` 指定目标分区；`bs=16M` 按 16 MiB 块写入，`status=progress` 显示进度，
`conv=fsync` 在成功结束前将数据刷到设备。写入失败时，处理原因后从本节重新完整写入。

## 5. 宿主机：全量校验

```bash
sudo cmp -n "$image_bytes" rv-rootfs.img /dev/sdb3
echo $?
```

`cmp -n` 将镜像与目标分区开头相同长度的内容逐字节比较。
没有差异输出且退出码为 `0` 才能继续；其他结果表示内容不一致或读取失败。
校验放在文件系统检查和扩容之前，因为后续操作会修改文件系统元数据。

## 6. 宿主机：检查并扩容

```bash
sudo e2fsck -fp /dev/sdb3
echo $?
```

`-f` 强制检查，`-p` 自动修复可安全处理的问题。退出码 `0` 表示无错误，`1` 表示已修复；
只在这两种情况下继续扩容：

```bash
sudo e2fsck -f /dev/sdb3
sudo resize2fs /dev/sdb3
sudo e2label /dev/sdb3 ''
```

`resize2fs` 将 ext4 扩展到第三分区的全部容量；`e2label` 沿用原流程清空卷标，
启动时使用明确的分区路径。上述操作不改变分区边界。

```bash
sudo e2fsck -fn /dev/sdb3
echo $?
```

`-fn` 做完整只读复查。必须完成检查且退出码为 `0`，再进行下一步。

## 7. 宿主机：安全拔卡

```bash
sync
udisksctl power-off -b /dev/sdb
```

`sync` 刷新写入，`udisksctl power-off -b` 安全关闭指定的读卡器设备。
若提示其他分区仍在使用，先释放其占用再重试。成功后拔出读卡器，将 SD 卡装回 VF2。

## 8. VF2：选择根分区并启动

按[启动指令](VF2开发板启动命令.md)连接串口、进入 U-Boot、加载内核并准备 DTB。
在执行 `go` 启动前，将根分区设置为本次烧录的第三分区：

```text
fdt set /chosen bootargs "root=/dev/mmcblk1p3 rw"
```

该命令设置本次启动使用的根分区。继续启动后应进入 `starry:~#`。

如需改写第四分区，将烧录流程中的宿主机目标统一替换为实际第四分区设备，
启动参数对应使用 `root=/dev/mmcblk1p4 rw`。第五分区保留为 swap。
