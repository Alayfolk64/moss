# 龙芯 2K1000LA 上板常用指令

本文记录龙芯 2K1000LA 星云版上构建、传输和启动 MOSS 的常用操作。
基本流程和 VisionFive 2 相同：通过串口进入 U-Boot，用 TFTP 把 MOSS 内核加载到内存，
然后启动内核。

2K1000LA 的主要区别是：

- rootfs 位于板载 SATA 硬盘，而不是 SD 卡。
- MOSS 启动时需要 U-Boot 把 DTB 的内存地址传给内核。
- DTB 可以直接复用原厂 U-Boot 已经加载的板载设备树，不需要每次从 PC 下载。

| 项目 | 当前配置 |
| --- | --- |
| 串口 | `/dev/ttyUSB0`，115200 8N1 |
| PC 有线网卡 | `enp3s0` |
| PC IP | `192.168.88.1` |
| 板卡 IP | `192.168.88.2` |
| TFTP 目录 | `/srv/tftp` |
| MOSS 加载地址 | `0x9000000098000000` |
| MOSS 入口地址 | `0x9000000098000040` |
| DTB 工作副本地址 | `0x900000000a000000` |

> 本文中的 `setenv` 只影响当次启动。不要执行 `saveenv`，不要擦写 SPI，
> 也不会覆盖板子原有的 Linux。

## 1. 板子当前的系统和硬盘

板子保留原厂 U-Boot 和 Linux。默认启动流程是：

```text
SPI 中的 U-Boot -> SATA 硬盘上的原厂 Linux
```

当我们手工进入 U-Boot 启动 MOSS 时：

```text
SPI 中的 U-Boot -> TFTP 加载 MOSS 到内存 -> MOSS 使用 SATA 上的 rootfs
```

2026-08-19 的最新烧录记录已将原 sda2/sda3 合并。当前布局如下，详见[烧录教程](龙芯二号板烧录教程.md)：

| 分区 | 内容 | 用途 |
| --- | --- | --- |
| `/dev/sda1` | 原厂 Linux | 板子默认启动的系统，保留不动 |
| `/dev/sda2` | 18 GiB Alpine/musl rootfs | 当前交互环境 |

原布局是 sda2 的 12 GiB glibc 环境和 sda3 的 6 GiB Alpine 环境。合并后 sda3 不存在；本文保留的旧布局操作仅在按烧录教程恢复分区后使用。

MOSS 内核通过 TFTP 临时进入内存，不会写入 SPI。重启后如果不再截停 U-Boot，
板子仍会返回原厂 Linux。

## 2. 接线

- USB 串口连接 PC，用于查看 U-Boot 和 MOSS 日志。
- 网线直连 PC 与 2K1000LA，用于 TFTP 传输 MOSS 内核。
- 保持板载 SATA 硬盘连接稳定。

当前串口设备为：

```bash
ls -l /dev/ttyUSB0
```

## 3. 构建 MOSS

首次上板建议使用交互镜像：

```bash
cd /home/wuxun/Projects/moss-dev
make site-2kla
```

生成文件：

```text
build/site-2kla/moss-2kla.bin
```

该镜像按 2 核、2 GiB 构建，启动后进入 BusyBox shell，适合手工执行命令。龙芯不再生成自动执行版。

## 4. 配置 PC 网口和 TFTP

2K1000LA 固定使用 PC 的 `enp3s0` 直连网口和 `192.168.88.0/24` 网段。VF2 单板运行时也默认使用
`enp3s0`，但地址为 `192.168.89.0/24`；两块板同时连接时，VF2 才改接 `enx6c1ff75c0e36`。
本节只配置 2K1000LA。当前 2K1000LA 一侧的 PC 地址固定为 `192.168.88.1`：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
ip addr show enp3s0
```

复制镜像到 TFTP 目录：

```bash
sudo cp build/site-2kla/moss-2kla.bin /srv/tftp/moss-2kla.bin
```


检查 TFTP 服务：

```bash
ps -ef | grep '[i]n.tftpd'
```

如果服务未运行：

```bash
sudo /usr/sbin/in.tftpd --listen --user tftp \
  --address 192.168.88.1:69 --secure /srv/tftp
```

## 5. 打开串口并进入 U-Boot

打开 picocom：

```bash
picocom -b 115200 /dev/ttyUSB0

```

常用按键：

- `Ctrl-A` 后按 `Ctrl + X`：退出 picocom。
- 在 MOSS shell 中按 `Ctrl-C`：中断当前前台程序。

2K1000LA 的原厂 U-Boot 自动启动很快，而且会清空很早的串口输入。复位或上电后，
连续按 `c`，直到出现：

```text
=>
```

不要执行 `saveenv`。

## 6. 使用已验证的实板 DTB

DTB 由 MOSS 内核读取和解析，但 U-Boot 需要先把 DTB 放在内存中，并在启动内核时
传入它的地址。

历史真机验收使用的是 TFTP 目录中单独保存的 `board.dtb`，不是
U-Boot 的 `fdtcontroladdr` control DTB。在 PC 上先确认文件存在：

```bash
test -s /srv/tftp/board.dtb && ls -l /srv/tftp/board.dtb
```

如果该文件不存在，不要改用 `fdtcontroladdr`。两份 DTB 的内存布局和节点结构
不同，control DTB 不能用于当前 MOSS 启动。

## 7. 加载并启动 MOSS

先在 U-Boot `=>` 下设置网络，下载实板 DTB，再补齐 MOSS 当前需要的
网卡和 AHCI 设备树属性：

```text
setenv ipaddr 192.168.88.2
setenv serverip 192.168.88.1
setenv netmask 255.255.255.0
setenv ethact ethernet@40040000

tftpboot 0x900000000a000000 board.dtb
fdt addr 0x900000000a000000
fdt resize 4096

fdt set /aliases ethernet0 /2k1000-soc/ethernet@40040000
fdt set /2k1000-soc/ahci@400e0000 ports-implemented <0x1>

fdt print /aliases ethernet0
fdt print /2k1000-soc/ahci@400e0000 ports-implemented
```

### 7.1 启动当前交互环境 `/dev/sda2`

```text
fdt set /chosen bootargs root=/dev/sda2

tftpboot 0x9000000098000000 moss-2kla.bin
go 0x9000000098000040 0x900000000a000000
```

启动后应进入：

```text
starry:~#
```

### 7.2 旧双分区布局的比赛环境

只有已恢复旧布局并将 glibc 比赛镜像烧入 sda2 时，才使用本节运行 cagent/buildstorm。当前合并后的 Alpine sda2 不等于该环境。旧布局中的 Alpine 使用 sda3。

如果使用交互镜像手动运行测试：

```text
fdt set /chosen bootargs root=/dev/sda2
tftpboot 0x9000000098000000 moss-2kla.bin
go 0x9000000098000040 0x900000000a000000
```

## 8. MOSS 启动后的常用检查

```sh
uname -m
nproc
cat /sys/devices/system/cpu/online
cat /proc/cpuinfo
cat /proc/meminfo
free -h
mount
df -h /
ip addr
```

当前目标配置是 2 核、2 GiB 内存：

- `uname -m` 应为 `loongarch64`。
- `nproc` 应为 `2`。
- CPU online 应为 `0-1`。

U-Boot banner 中的 `2G-factory` 不是真实内存容量，当前板子的实际基线是 1 GiB。

## 10. PC 和 MOSS 之间传文件

断网时仍可以使用 PC 和板卡之间的直连网络。

在 PC 的文件所在目录执行：

```bash
python3 -m http.server 8000 --bind 192.168.88.1
```

在 MOSS 中执行：

```sh
cd /root
wget http://192.168.88.1:8000/<文件名>
sync
sha256sum <文件名>
```

可以在 PC 和 MOSS 两端分别执行 `sha256sum`，确认文件完整。

## 11. 安全重启

在 MOSS 中执行：

```sh
sync
reboot
```

也可以在交互 init shell 中执行：

```sh
exit
```

内核会先同步并卸载文件系统，然后重启。不要在 MOSS 运行期间直接断电，
也不要使用 `reboot -f`。

## 12. 常见问题

- **进不去 U-Boot**：复位后连续按 `c`，不要只按一次。
- **`board.dtb` 不存在**：先恢复历史真机验证过的备份；不要改用
  `fdtcontroladdr`，也不要把静态测试用 DTS fixture 当成实板 DTB。
- **`tftpboot` 失败**：检查 PC IP、网线、TFTP 进程和 `/srv/tftp/moss-2kla.bin`。
- **MOSS 找不到根分区**：确认 `/chosen/bootargs`：当前合并布局使用
  `root=/dev/sda2`；旧布局按实际镜像选择分区。
- **原厂 Linux 已经挂载 sda2/sda3**：在 Linux 中先执行 `umount /dev/sda3`、`sync` 和
  `reboot`，再截停 U-Boot。冷启动时在 Linux 运行前直接截停 U-Boot，则不存在同时挂载问题。
- **断网时显示 NTP 失败**：等待尝试结束，之后仍会进入 `starry:~#`，不影响离线操作。

## 14. 可变值、查询和修改补充

本节不替代前面的流程。当前 PC 直连网卡是 `enp3s0`。串口名、网卡名、IP、TFTP
路径、根分区和文件哈希都可能变化；三个
加载/入口地址仍按前文已验证值使用。

PC 上查询：

```bash
ip -br addr
ip route
ls -l /dev/serial/by-id/
cat /etc/default/tftpd-hpa
sha256sum build/site-2kla/moss-2kla.bin /srv/tftp/moss-2kla.bin
```

MOSS 中查询：

```sh
cat /proc/cmdline
mount | head
ip addr
ip route
cat /etc/resolv.conf
echo "$PATH"
```

临时修改网络：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
```

```sh
ip addr replace 192.168.88.2/24 dev eth0
ip route replace default via 192.168.88.1
echo nameserver 223.5.5.5 > /etc/resolv.conf
```

PC 网络持久修改使用 `sudo nmtui`；TFTP 配置修改后执行
`sudo systemctl restart tftpd-hpa`。MOSS 默认 IP/网关修改 `Makefile` 的 `site-2kla` 目标，
PATH 修改 `src/init_site.sh`，然后重新执行 `make site-2kla`。切换根分区仍按前文修改
`root=/dev/sda2` 或 `root=/dev/sda3`，不要执行 `saveenv`。

PC 时间正确时，用下面命令生成一条可直接复制到 MOSS 的校时命令：

```bash
date -u '+busybox date -u -s %Y%m%d%H%M.%S'
```

`starry:~#` 说明编译进内核的 `src/init_site.sh` 已执行；它不会写成根文件系统里的
`/init_site.sh`。旧内核 PATH 少 `/usr/bin` 时可临时 `export PATH=/usr/bin:$PATH`。

2026-08-19 实板复测已修复 `ping` 刷屏：以下命令只输出 3 条回包，3/3、0% 丢包。

```sh
ping -c 3 192.168.88.1
```

Alpine 不允许 `pip` 直接改系统 Python，需在虚拟环境中安装：

```sh
python3 -m venv /root/pip-test
. /root/pip-test/bin/activate
python -m pip install --no-cache-dir requests
python -c 'import requests; print(requests.__version__)'
```

实板验收输出版本 `2.34.2`。如果 DNS 或外网突然失败，先在 PC 重查
`ip -br addr` 和 `ip route`，确认 `enp3s0` 只保留 `192.168.88.1/24`且 Wi-Fi 仍是默认出口。
