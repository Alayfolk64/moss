# 龙芯 2K1000LA 上板常用指令

本文记录龙芯 2K1000LA 星云版上构建、传输和启动 MOSS 的常用操作。
通过串口进入 U-Boot，用 TFTP 把 MOSS 内核和实板 DTB 加载到内存，然后启动内核。

本文中的宿主机项目路径均相对于 `moss` 项目根目录。构建、复制内核和校验哈希时，
都在该目录下执行命令。

接好 USB 串口后，先在宿主机终端连接板子：

```bash
picocom -b 115200 /dev/ttyUSB0
```

`-b 115200` 设置波特率，`/dev/ttyUSB0` 是串口设备。
保持串口连接，后续构建和网络配置在另一个宿主机终端执行。
退出 picocom 时，先按 `Ctrl-A`，再按 `Ctrl-X`；在板端 shell 中按 `Ctrl-C` 可中断前台程序。

本板的启动配置如下：

- rootfs 位于板载 SATA 硬盘的 `/dev/sda2` 分区。
- MOSS 启动时需要 U-Boot 把 DTB 的内存地址传给内核。
- DTB 使用仓库中的 `boards/2k1000la/board.dtb`，复制到 TFTP 目录后加载。

| 项目 | 当前配置 |
| --- | --- |
| 串口 | `/dev/ttyUSB0`，115200 8N1 |
| PC 有线网卡 | `enp3s0` |
| PC IP | `192.168.88.1` |
| 板卡 IP | `192.168.88.2` |
| TFTP 目录 | `/srv/tftp` |
| MOSS 加载地址 | `0x9000000098000000` |
| MOSS 入口地址 | `0x9000000098000040` |
| DTB 工作副本地址 | `0x900000000a000000` |

> 本文中的 `setenv` 只影响当次启动。不要执行 `saveenv`，不要擦写 SPI，
> 也不会覆盖板子原有的 Linux。

## 1. 板子当前的系统和硬盘

板子保留原厂 U-Boot 和 Linux。默认启动流程是：

```text
SPI 中的 U-Boot -> SATA 硬盘上的原厂 Linux
```

当我们手工进入 U-Boot 启动 MOSS 时：

```text
SPI 中的 U-Boot -> TFTP 加载 MOSS 到内存 -> MOSS 使用 SATA 上的 rootfs
```

统一保留原厂 Linux 和一个 MOSS 根文件系统分区。`sdcard-la-pub.img.gz` 先在宿主机缩容，
再烧录到现有 `/dev/sda2` 并扩容，详见[烧录教程](龙芯二号板烧录教程.md)：

| 分区 | 内容 | 用途 |
| --- | --- | --- |
| `/dev/sda1` | 原厂 Linux | 板子默认启动的系统，保留不动 |
| `/dev/sda2` | 烧录后的 rootfs | MOSS 交互环境，使用该分区全部容量 |

MOSS 内核通过 TFTP 临时进入内存，不会写入 SPI。重启后如果不再截停 U-Boot，
板子仍会返回原厂 Linux。

## 2. 接线

- USB 串口连接 PC，用于查看 U-Boot 和 MOSS 日志。
- 网线直连 PC 与 2K1000LA，用于 TFTP 传输 MOSS 内核。
- 保持板载 SATA 硬盘连接稳定。

当前串口设备为：

```bash
ls -l /dev/ttyUSB0
```

## 3. 构建 MOSS

在 `moss` 项目根目录构建交互镜像：

```bash
make site-2kla
```

生成文件：

```text
build/site-2kla/moss-2kla.bin
```

该镜像按 2 核、2 GiB 构建，启动后进入交互 shell，适合手工执行命令。龙芯不再生成自动执行版。

## 4. 配置 PC 网口和 TFTP

PC 使用 `enp3s0` 网口直连 2K1000LA，网段为 `192.168.88.0/24`。
PC 地址为 `192.168.88.1`，板卡地址为 `192.168.88.2`。在 PC 上执行：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
ip addr show enp3s0
```

在 `moss` 项目根目录，将内核和仓库中的 DTB 复制到 TFTP 目录：

```bash
sudo cp build/site-2kla/moss-2kla.bin /srv/tftp/moss-2kla.bin
sudo cp boards/2k1000la/board.dtb /srv/tftp/board.dtb
```

第一条复制构建出的 MOSS 内核，第二条复制仓库保存的实板设备树。

检查 TFTP 端口：

```bash
sudo ss -lunp 'sport = :69'
```

`-lunp` 显示监听中的 UDP 端口及进程，只查看 69 端口。
若没有服务监听 `192.168.88.1:69` 或 `0.0.0.0:69`，执行：

```bash
sudo /usr/sbin/in.tftpd --listen --user tftp \
  --address 192.168.88.1:69 --secure /srv/tftp
```

## 5. 进入 U-Boot

保持开头建立的串口连接，在原厂 Linux 的 `[root@LS-GD ~]#` 下执行：

```sh
sync
reboot
```

`sync` 将写入刷到磁盘，`reboot` 正常重启板子。
2K1000LA 的原厂 U-Boot 自动启动很快，而且会清空很早的串口输入。重启后，
连续按 `c`，直到出现：

```text
=>
```

## 6. 使用仓库中的实板 DTB

DTB 由 MOSS 内核读取和解析，但 U-Boot 需要先把 DTB 放在内存中，并在启动内核时
传入它的地址。

使用仓库中的 [boards/2k1000la/board.dtb](../../../boards/2k1000la/board.dtb)。
该文件原样归档自现有上板流程使用的 `/srv/tftp/board.dtb`，型号为 `LS2K1000-DP-FACTORY`，
大小为 22,612 字节。第 4 节已将它复制到 TFTP 目录，下面直接加载 `board.dtb`。

加载后，按下一节命令设置启动参数、网卡别名和 AHCI 属性。

## 7. 加载并启动 MOSS

先在 U-Boot `=>` 下设置网络，下载实板 DTB，再补齐 MOSS 当前需要的
网卡和 AHCI 设备树属性：

```text
setenv ipaddr 192.168.88.2
setenv serverip 192.168.88.1
setenv netmask 255.255.255.0
setenv ethact ethernet@40040000

tftpboot 0x900000000a000000 board.dtb
fdt addr 0x900000000a000000
fdt resize 4096

fdt set /aliases ethernet0 /2k1000-soc/ethernet@40040000
fdt set /2k1000-soc/ahci@400e0000 ports-implemented <0x1>

fdt print /aliases ethernet0
fdt print /2k1000-soc/ahci@400e0000 ports-implemented
```

### 7.1 启动当前交互环境 `/dev/sda2`

```text
fdt set /chosen bootargs root=/dev/sda2

tftpboot 0x9000000098000000 moss-2kla.bin
go 0x9000000098000040 0x900000000a000000
```

启动后应进入：

```text
starry:~#
```

### 7.2 校准 MOSS 时间

看到 `starry:~#` 后立即校时。在**宿主机终端**确认时间正确，然后生成校时命令：

```bash
date -u '+date -u -s "%Y-%m-%d %H:%M:%S"'
```

`-u` 使用 UTC，格式化字符串生成带引号的 `年-月-日 时:分:秒`，`-s` 用于设置时间。
复制输出的完整一行，保留双引号，切回串口终端，在 MOSS 的 `starry:~#` 下粘贴并回车。
校时完成后再执行后面的检查和比赛脚本。

## 8. MOSS 启动后的常用检查

```sh
uname -m
nproc
cat /sys/devices/system/cpu/online
cat /proc/cpuinfo
cat /proc/meminfo
free -h
mount
df -h /
ip addr
```

当前目标配置是 2 核、2 GiB 内存：

- `uname -m` 应为 `loongarch64`。
- `nproc` 应为 `2`。
- CPU online 应为 `0-1`。

## 9. 运行比赛脚本

在使用 `/dev/sda2` 启动的交互 shell 中：

```sh
cd /glibc
bash ./cagent_testcode.sh
```

```sh
cd /glibc
bash ./buildstorm_testcode.sh
```

在当前开发板运行 buildstorm 测例所需时间长，实测为 5701s，尤其是 ax-posix-api 编译时间过长。
OS大赛发放的开发板的物理内存为 2GB（手册描述该型号开发板只有 1GB 物理内存）,加上 swap 分区才得以运行 buildstorm 测例。

镜像中已安装的现场工具可这样检查：

```sh
git --version
vim --version
gcc --version
rustc --version
```

## 10. 安全重启

在 MOSS 中执行：

```sh
sync
reboot
```

也可以在交互 init shell 中执行：

```sh
exit
```

内核会先同步并卸载文件系统，然后重启。不要在 MOSS 运行期间直接断电，
也不要使用 `reboot -f`。

## 11. 常见问题

- **进不去 U-Boot**：复位后连续按 `c`，不要只按一次。
- **TFTP 目录中缺少 `board.dtb`**：按第 4 节，将仓库中的 `boards/2k1000la/board.dtb`
  重新复制到 `/srv/tftp/board.dtb`。
- **`tftpboot` 失败**：检查 PC IP、网线、TFTP 进程和 `/srv/tftp/moss-2kla.bin`。
- **MOSS 找不到根分区**：确认 `/chosen/bootargs` 使用 `root=/dev/sda2`。
- **原厂 Linux 已经挂载 sda2**：需要在 Linux 中烧录或检查时，按[烧录教程](龙芯二号板烧录教程.md#4-板端确认目标并解除占用)
  解除占用；需要转入 MOSS 时，正常执行 `sync`、`reboot`，再截停 U-Boot。
  冷启动时在 Linux 运行前直接截停 U-Boot，则不存在同时挂载问题。
