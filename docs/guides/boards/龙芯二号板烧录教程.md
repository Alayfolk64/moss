# 龙芯二号板通过原厂 Linux 网络烧录镜像

更新日期：2026-08-19

本文记录没有 SATA-USB 转接器时，把 PC 上的 rootfs 镜像通过网络传给龙芯 2K1000LA
板上的原厂 Linux，并直接写入 SATA 的 `sda2` 或 `sda3`。需要一个大 rootfs 时，按第 1 节
把相邻的 `sda3` 和 `sda2` 合成一个 18 GiB 的新 `sda2`；需要恢复两个比赛环境时，按第 8 节
重新拆分为 6 GiB `sda3` 和 12 GiB `sda2`。

数据路径是：

```text
PC 镜像 -> /srv/tftp -> 临时 HTTP -> 原厂 Linux wget -> /dev/sda2 或 /dev/sda3
```

整个过程不把镜像保存到 `sda1`，因此不会额外占用原厂 Linux 根分区的空间。

2026-08-19 实板当前已经采用合并布局：`sda1` 保留原厂 Linux，`sda2` 是 18 GiB
Alpine/musl rootfs，`sda3` 不存在。当前 musl 重新烧录按第 2、3、5、6 节执行。

需要改变布局时再选下面的路径：

- 烧录 Alpine 到 `sda3`：按第 2、3、4、6 节执行；
- 烧录 MOSS/Debian 到 `sda2`：按第 2、3、5、6 节执行。
- 需要单个 18 GiB rootfs：先按第 1 节合并，再按第 2、3、5、6 节执行；
- 需要恢复 6 GiB + 12 GiB 双分区：按第 8 节拆分，再分别烧录两个分区；
- 镜像大于 18 GiB：当前 SATA 布局放不下，停止操作，不能继续写盘。

## 1. 合并 `sda3` 和 `sda2` 为 18 GiB rootfs

### 1.1 什么时候需要合并

先在 PC 上检查已经解压的源镜像，路径按实际文件修改：

```bash
stat -c '%n %s bytes' /home/wuxun/Downloads/rootfs.img
```

需要让单个 rootfs 使用完整 18 GiB，或者镜像大于 `12884901888` bytes（12 GiB）、但不大于
`19327352832` bytes（18 GiB）时，执行本节。当前实板已经完成合并，不要重复执行。

镜像本身不超过原分区、只是烧录后文件系统显示空间很小或 100% 时，不需要为了这个现象合并，
应在目标分区未挂载时执行 `e2fsck` 和 `resize2fs`；第 4、5 节已经包含这个步骤。

当前三个分区在磁盘上的物理顺序是 `sda1 -> sda3 -> sda2`：

| 物理顺序 | 分区 | 起始 sector | sector 数 | 容量 | 用途 |
| ---: | --- | ---: | ---: | ---: | --- |
| 1 | `/dev/sda1` | 2048 | 24780800 | 约 11.8 GiB | 原厂 Linux、旧内核、swapfile |
| 2 | `/dev/sda3` | 24782848 | 12582912 | 严格 6 GiB | LoongArch64 Alpine 环境 |
| 3 | `/dev/sda2` | 37365760 | 25165824 | 严格 12 GiB | MOSS/Debian glibc 环境 |

因为 `sda3` 和 `sda2` 物理连续，所以可以删除 `sda3` 的分区入口，并把 `sda2` 的起点向前
移动，得到下面的布局：

| 分区 | 起始 sector | sector 数 | 容量 | 用途 |
| --- | ---: | ---: | ---: | --- |
| `/dev/sda1` | 2048 | 24780800 | 约 11.8 GiB | 原厂 Linux，保持不变 |
| `/dev/sda2` | 24782848 | 37748736 | 严格 18 GiB | 合并后的 rootfs 分区 |

合并不会把两个分区中的文件拼在一起。它会让原 `sda2` 和 `sda3` 的文件系统都不可再使用，
后面必须向新的 `/dev/sda2` 完整烧录镜像。需要保留的数据必须先复制到 PC。

> 合并只允许改 `sda2` 和 `sda3`。绝对不得写 `/dev/sda` 整盘，也不得删除、移动或格式化
> `/dev/sda1`，否则会破坏原厂 Linux 和恢复入口。

### 1.2 从原厂 Linux 核对并备份分区表

必须启动原厂 Linux，并确认当前根分区是 `/dev/sda1`：

```bash
findmnt -no SOURCE /
cat /sys/block/sda/size
sfdisk --dump /dev/sda
sfdisk --verify /dev/sda
```

第一条必须输出 `/dev/sda1`，磁盘必须是 `62533296` sectors。`sfdisk --dump` 中三个分区的
起点和大小必须与 1.1 节的表完全相同；任意数字不同都停止操作。

把文本分区表和 512-byte MBR 扇区备份到不会被修改的 `sda1`。板上原厂 Linux 的旧版
`sfdisk` 不支持 `--backup-pt-sectors`，所以直接使用 `dd`：

```bash
mkdir -p /root/partition-backup
sfdisk --dump /dev/sda > /root/partition-backup/sda-before-merge.sfdisk
dd if=/dev/sda of=/root/partition-backup/sda-mbr-sector0.bin \
  bs=512 count=1
sync
sha256sum /root/partition-backup/*
```

同时保留本次串口日志。这个备份只能恢复分区表，不能恢复原 `sda2`、`sda3` 中的文件。

### 1.3 停止自动挂载并确认分区无人使用

原厂 Linux 的 `systemd-udevd` 可能在自己的 mount namespace 中自动挂载 `sda2`、`sda3`，
只看当前 shell 的 `findmnt` 不够。执行：

```bash
systemctl stop systemd-udevd-control.socket \
  systemd-udevd-kernel.socket systemd-udevd.service
umount /dev/sda2 2>/dev/null || true
umount /dev/sda3 2>/dev/null || true
swapoff /dev/sda2 2>/dev/null || true
swapoff /dev/sda3 2>/dev/null || true
sync

findmnt -rn -S /dev/sda2
findmnt -rn -S /dev/sda3
grep -sH -E '/dev/sda[23]' /proc/[0-9]*/mountinfo
grep -E '^/dev/sda[23]' /proc/swaps
```

最后四条必须全部没有输出。这里隐藏 `umount`、`swapoff` 的错误，是因为目标可能本来就没有
挂载或启用；后面的跨 namespace 检查才是最终安全条件。只要仍有一条输出，就不能改分区表。

### 1.4 合并为 18 GiB 的新 `sda2`

确认备份已经生成、所有检查均通过后，执行下面两条分区表写命令：

```bash
sfdisk --lock --delete /dev/sda 3
printf 'start=24782848, size=37748736, type=83\n' | \
  sfdisk --lock --no-reread --wipe never \
    --wipe-partitions never -N 2 /dev/sda
sync
reboot
```

第一条删除 `sda3` 的分区入口，第二条把 `sda2` 改成从原 `sda3` 起点开始、覆盖原两个分区
的 18 GiB 分区。`--wipe never` 保证 `sfdisk` 不额外擦除磁盘签名，但原两个文件系统仍然已经
失效，不能挂载。

因为原厂 Linux 正在使用同一磁盘上的 `sda1`，第一条命令会提示内核暂时无法重读分区表；
第二条的 `--no-reread` 允许只更新磁盘上的分区表，不使用旧的内核分区视图阻止操作。这也是
必须立即重启、不能继续使用旧 `/dev/sda2` 和 `/dev/sda3` 设备节点的原因。板卡重新进入原厂
Linux 后再检查：

```bash
sfdisk --dump /dev/sda
sfdisk --verify /dev/sda
cat /sys/class/block/sda2/size
test ! -e /sys/class/block/sda3 && echo 'sda3 removed'
```

结果必须只有原来的 `sda1` 和新的 `sda2`，其中：

```text
/dev/sda1 : start=2048,     size=24780800, type=83
/dev/sda2 : start=24782848, size=37748736, type=83
```

`cat /sys/class/block/sda2/size` 必须输出 `37748736`，并且出现 `sda3 removed`。从此烧录目标
统一使用 `/dev/sda2`，MOSS 启动参数仍然使用 `root=/dev/sda2`。重启后 `systemd-udevd` 会重新
启动，因此真正写镜像前必须再执行一遍 1.3 节，确认新的 `sda2` 在所有 mount namespace 中均
未挂载。

### 1.5 不合并时的保护边界

保持原三分区布局时，只允许按需覆盖下面的具体目标：

```text
/dev/sda2
/dev/sda3
```

> 绝对不得写 `/dev/sda` 整盘，否则会覆盖 MBR、原厂 Linux 和全部分区。

本文不写 SPI，也不执行 `saveenv`。

## 2. PC 端：把镜像复制到网络目录

PC 上的网络文件目录是：

```text
/srv/tftp
```

必须使用已解压的 `.img` 文件，不要把 `.xz` 压缩包直接写入 SATA 分区。

### 2.1 复制镜像

假设要烧录的镜像位于 `/home/wuxun/Downloads/rootfs.img`，执行：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
stat -c '%n %s bytes' \
  /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
sha256sum \
  /home/wuxun/Downloads/rootfs.img /srv/tftp/rootfs.img
```

第一条命令只删除上一次使用的统一临时副本 `/srv/tftp/rootfs.img`，不会删除
`/home/wuxun/Downloads` 中真正的源镜像。每次复制新镜像前都执行，避免误用旧镜像。

只需把第二条 `cp` 命令中的源路径换成实际镜像路径。目标文件统一叫做
`/srv/tftp/rootfs.img`，后面的板端命令就不需要再改文件名。`stat` 显示的两个字节数和
`sha256sum` 显示的两个哈希必须分别相同，否则不启动 HTTP、不写盘。

如果要烧录当前已验证的镜像，它们已经在 `/srv/tftp` 中，可以不再复制：

| 目标 | PC 上的镜像 | 字节数 | SHA-256 |
| --- | --- | ---: | --- |
| `sda2` | `/srv/tftp/sdcard-la-clean-12g-20260811.img` | 12,884,901,888 | `35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d` |
| `sda3` 或合并后的 18 GiB `sda2` | `/srv/tftp/alpine-linux-loongarch64.img` | 723,517,440（690 MiB） | `0ad295fc3e62dad2dd15ccf575135bc8c17fe8cddb510f3aa9ff44c4e1be2173` |

使用这两个现有镜像时，先把要烧录的那一个复制为统一文件名。例如烧录 Alpine：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /srv/tftp/alpine-linux-loongarch64.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
```

烧录 12 GiB MOSS/Debian 镜像时：

```bash
sudo rm -rf /srv/tftp/rootfs.img
sudo cp /srv/tftp/sdcard-la-clean-12g-20260811.img /srv/tftp/rootfs.img
sudo chown tftp:tftp /srv/tftp/rootfs.img
sudo chmod 0644 /srv/tftp/rootfs.img
```

### 2.2 记录源镜像的大小和哈希

```bash
stat -c '%n %s bytes' /srv/tftp/rootfs.img
sha256sum /srv/tftp/rootfs.img
```

把输出的字节数和 SHA-256 保留好。写盘后必须从板端分区读回同样多的字节，得到相同
SHA-256，才算烧录成功。

### 2.3 配置 PC 网口并启动 HTTP

当前连接龙芯板的 PC 网口是 `enp3s0`：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
ip -brief address show enp3s0
```

在 PC 的一个单独终端中启动 HTTP：

```bash
python3 -m http.server 8000 \
  --bind 192.168.88.1 \
  --directory /srv/tftp
```

保持这个终端运行。再打开另一个 PC 终端检查：

```bash
curl -I http://192.168.88.1:8000/rootfs.img
```

必须看到 `HTTP/1.0 200 OK` 和正确的 `Content-Length`。

## 3. 板端：进入原厂 Linux 并确认目标

烧录必须在板上原厂 Linux 中执行，不要在当前以 `sda2` 或 `sda3` 为根的 MOSS 中执行。

先检查磁盘和挂载点：

```bash
findmnt /
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS /dev/sda
```

必须确认：

- 原厂 Linux 的 `/` 在 `sda1`；
- 本次要写的 `sda2` 或 `sda3` 不是当前根分区。

配置板端网络：

```bash
ip link set eth0 up
ip address replace 192.168.88.2/24 dev eth0
ping -c 3 192.168.88.1
busybox wget -O /dev/null http://192.168.88.1:8000/board.dtb
```

`ping` 必须 0% 丢包，`wget` 必须成功。这里不需要公网、DNS、NAT 或 NTP，只使用 PC 和板卡
之间的直连网络。

## 4. 烧录 `sda3`（6 GiB Alpine）

只有要写 `sda3` 时才执行本节。

### 4.1 写盘前确认尺寸和卸载

```bash
cat /sys/class/block/sda3/size
```

必须输出：

```text
12582912
```

该数字乘以 512 bytes 就是严格 6 GiB。然后执行：

```bash
umount /dev/sda3 2>/dev/null || true
sync
findmnt -rn -S /dev/sda3
```

`findmnt` 必须没有任何输出。`umount` 的错误被隐藏，是因为分区本来就可能没有挂载；最后的
`findmnt` 才是必须通过的安全检查。

### 4.2 通过网络直接写入

```bash
busybox wget -O /dev/sda3 http://192.168.88.1:8000/rootfs.img
echo "wget_rc=$?"
sync
```

必须看到：

```text
wget_rc=0
```

如果断网、重启或 `wget_rc` 不是 0，此时分区内容不完整，不要挂载或启动。修复网络后重新执行
同一条 `wget -O /dev/sda3 ...` 从头覆盖即可。

### 4.3 读回哈希并扩展 ext4

当前 Alpine 镜像是精确 690 MiB，执行：

```bash
dd if=/dev/sda3 bs=1M count=690 iflag=fullblock | sha256sum
```

必须得到：

```text
0ad295fc3e62dad2dd15ccf575135bc8c17fe8cddb510f3aa9ff44c4e1be2173
```

只有哈希一致后，才执行：

```bash
e2fsck -f -y /dev/sda3
resize2fs /dev/sda3
e2fsck -f -n /dev/sda3
```

最后一条 `e2fsck` 必须完成五个检查阶段且没有文件系统错误。

## 5. 烧录 `sda2`（12 GiB 普通布局或 18 GiB 合并布局）

只有要写 `sda2` 时才执行本节。镜像不超过 12 GiB 时可以使用原来的 12 GiB `sda2`；镜像
大于 12 GiB、但不超过 18 GiB 时，必须先按第 1 节完成合并。

### 5.1 写盘前确认尺寸和卸载

```bash
cat /sys/class/block/sda2/size
```

普通布局必须输出 `25165824`，合并布局必须输出 `37748736`：

```text
25165824    # 12 GiB 普通布局
37748736    # 18 GiB 合并布局
```

除此之外的数值都停止烧录。PC 上 `/srv/tftp/rootfs.img` 的字节数必须小于或等于对应分区容量：

```text
12 GiB = 12884901888 bytes
18 GiB = 19327352832 bytes
```

然后执行：

```bash
umount /dev/sda2 2>/dev/null || true
sync
findmnt -rn -S /dev/sda2
```

`findmnt` 必须没有任何输出。

### 5.2 通过网络直接写入

```bash
busybox wget -O /dev/sda2 http://192.168.88.1:8000/rootfs.img
echo "wget_rc=$?"
sync
```

必须看到 `wget_rc=0`。如果镜像大于目标分区，写到分区末尾会返回 ENOSPC，此时目标只有一份
不完整镜像，不能挂载或启动。

### 5.3 按源镜像字节数读回验证

如果烧录的是当前已验证的 12 GiB 镜像，而且目标仍是普通 12 GiB `sda2`，可以直接读取整个
分区：

```bash
dd if=/dev/sda2 bs=16M iflag=fullblock | sha256sum
```

必须得到：

```text
35681b35f3fc73dbeec258a230e5781f22fd718b265c40f1ddfa668984be322d
```

合并后烧录其他镜像时，把 PC 上 `stat` 记录的实际字节数填入 `image_bytes`。下面只读取镜像
实际覆盖的范围，不把 18 GiB 分区尾部尚未使用的空间算入哈希：

```bash
image_bytes=在这里填写PC记录的镜像字节数
dd if=/dev/sda2 bs=4M count="$image_bytes" \
  iflag=fullblock,count_bytes | sha256sum
```

摘要必须与 PC 上 `/srv/tftp/rootfs.img` 的 SHA-256 完全相同。`count_bytes` 让 `count` 按 bytes
解释，即使镜像大小不是 4 MiB 的整数倍也能精确校验。

确认哈希一致后，如果镜像内是 ext4，修复并扩展到整个目标分区：

```bash
e2fsck -f -y /dev/sda2
resize2fs /dev/sda2
e2fsck -f -n /dev/sda2
```

当前 12 GiB 镜像本身已经占满普通 12 GiB 分区，`resize2fs` 会报告无需扩展；较小的 ext4
镜像写入 18 GiB 合并分区后则必须执行这一步，否则系统仍只能看到镜像内部原有的容量。

2026-08-19 实板使用 `alpine-linux-loongarch64.img` 完成过这一流程。扩容后的 `/dev/sda2`
为 `4718592` 个 4 KiB blocks；MOSS 中可用 `4494114` blocks，约 17.1 GiB。

## 6. 完成、关机和启动

无论写 `sda2` 还是 `sda3`，最后都执行：

```bash
sync
lsblk -o NAME,SIZE,FSTYPE,LABEL,UUID,MOUNTPOINTS /dev/sda
```

需要关机时：

```bash
poweroff
```

完全关机后再断电。PC 上的 HTTP 终端按 `Ctrl+C` 停止服务。

镜像烧录完成后，MOSS 内核仍由 U-Boot 通过 TFTP 加载到 RAM，并在 bootargs 中选择
`root=/dev/sda2` 或 `root=/dev/sda3`。启动命令见
[龙芯二号板当前使用指南](2K1000LA板-启动指令.md)。

## 7. 最简验收标准

只要同时满足下面四项，就可以判定烧录成功：

1. PC 上 `curl -I` 返回 `200 OK` 和正确的 `Content-Length`；
2. 板端写入前 `findmnt` 和 `/proc/[0-9]*/mountinfo` 都没有显示目标分区被挂载；
3. `wget_rc=0`，且从块设备读回的 SHA-256 与 PC 源镜像一致；
4. 目标分区的 `e2fsck -f -n` 检查通过。

其中任意一项不满足，都不要启动该分区。

## 8. 将 18 GiB `sda2` 拆回 6 GiB `sda3` + 12 GiB `sda2`

本节用于恢复原来的双比赛环境布局。拆分会销毁当前 18 GiB `sda2` 文件系统；它不会自动把
其中的文件分别搬到新分区。需要保留的数据必须先复制到 PC，拆分完成后两个目标分区都必须
重新烧录。

### 8.1 从原厂 Linux 核对、备份并卸载

不能在以 18 GiB `/dev/sda2` 为根的 MOSS 中拆分。退出 MOSS，启动原厂 Linux，并核对当前根、
整盘大小和合并布局：

```bash
findmnt -no SOURCE /
cat /sys/block/sda/size
sfdisk --dump /dev/sda
sfdisk --verify /dev/sda
```

必须满足：

```text
root        = /dev/sda1
disk sectors = 62533296
/dev/sda1 : start=2048,     size=24780800, type=83
/dev/sda2 : start=24782848, size=37748736, type=83
```

任意数字不同都停止操作。备份当前分区表和 MBR：

```bash
mkdir -p /root/partition-backup
sfdisk --dump /dev/sda > /root/partition-backup/sda-before-split.sfdisk
dd if=/dev/sda of=/root/partition-backup/sda-before-split-mbr.bin \
  bs=512 count=1
sync
sha256sum /root/partition-backup/*
```

然后执行第 1.3 节的全部命令。`findmnt`、所有进程的 `mountinfo` 和 `/proc/swaps` 检查必须
没有 `/dev/sda2` 输出，才能继续。

### 8.2 写回原三分区边界

确认数据已备份、18 GiB `sda2` 未挂载后，严格按下面顺序执行：

```bash
sfdisk --lock --delete /dev/sda 2
printf 'start=37365760, size=25165824, type=83\n' | \
  sfdisk --lock --no-reread --wipe never \
    --wipe-partitions never -N 2 /dev/sda
printf 'start=24782848, size=12582912, type=83\n' | \
  sfdisk --lock --no-reread --wipe never \
    --wipe-partitions never -N 3 /dev/sda
sync
reboot
```

必须先创建编号 2，再创建编号 3；当前实板的 `sfdisk` 在编号 2 不存在时不会可靠保留编号 3。
创建时出现 `partition 2/3 is not defined yet` 警告是正常的，但其他错误都必须停止操作。不要在
重启前挂载或写入旧的分区设备节点。

### 8.3 重启后验收并重新烧录

重新进入原厂 Linux 后执行：

```bash
sfdisk --dump /dev/sda
sfdisk --verify /dev/sda
cat /sys/class/block/sda2/size
cat /sys/class/block/sda3/size
```

结果必须精确为：

```text
/dev/sda1 : start=2048,     size=24780800, type=83
/dev/sda3 : start=24782848, size=12582912, type=83
/dev/sda2 : start=37365760, size=25165824, type=83
sda2 size = 25165824
sda3 size = 12582912
```

这时只有分区边界恢复，原 18 GiB 文件系统已经不可用。再次停止 udev 自动挂载后，按第 4 节
把 Alpine/musl 镜像烧入 `sda3`，按第 5 节把 12 GiB MOSS/Debian 镜像烧入 `sda2`。以后启动
musl 使用 `root=/dev/sda3`，启动 glibc 使用 `root=/dev/sda2`。
