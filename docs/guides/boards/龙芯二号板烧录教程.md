# 龙芯二号板：缩容镜像、烧录 sda2、扩容

更新日期：2026-10-31

从[百度网盘](https://pan.baidu.com/s/1zTb2NPCp9HE_l_M-3-oczg?pwd=kyva)下载镜像 `sdcard-la-pub.img.gz`，
提取码 `kyva`，放到 `moss/rootfs/` 目录下。下面的宿主机操作从 `moss` 项目根目录开始。

```text
宿主机解压 → 检查并缩容 la-rootfs.img → HTTP 传到 /dev/sda2 → 板端检查、扩容 → 挂载
```

保留 `/dev/sda1` 的原厂 Linux，只使用 `/dev/sda2` 作为 MOSS 根文件系统分区。
不修改分区表，不合并或拆分分区，不写 `/dev/sda` 整盘。烧录会覆盖 `/dev/sda2` 的原有内容，
需要保留的文件先备份到其他设备。

命令按宿主机、板端分别执行。逐段运行，报错就停止，不隐藏错误。
`e2fsck` 的退出码 `0` 表示没有错误，`1` 表示已修复；其他退出码先处理，不继续烧录或扩容。

## 1. 宿主机：解压并缩容

本次镜像已经确认是**单个 ext4 文件系统镜像，不含分区表**。解压后的逻辑大小为 14 GiB，
不能用压缩包大小或稀疏文件的实际占用判断烧录长度：网络传输和写盘仍按镜像的逻辑长度进行。
先缩小文件系统，才能减少传输量和写盘量。

在宿主机终端执行：

```bash
cd rootfs
gzip -dc sdcard-la-pub.img.gz > la-rootfs.img
```

`cd` 进入镜像所在目录；`gzip -d` 解压，`-c` 把结果输出到 `la-rootfs.img`，
保留原 `.gz` 文件。解压期间需要至少 14 GiB 空闲空间。再次执行会覆盖这个工作副本。

```bash
e2fsck -fp la-rootfs.img
echo $?
```

`-f` 强制完整检查，`-p` 自动完成可安全处理的修复，包括必要的日志回放。
`echo $?` 显示上一条命令的退出码；只在输出 `0` 或 `1` 时继续。

```bash
resize2fs -M la-rootfs.img
```

`-M` 把文件系统缩到工具计算的最小容量，并自动缩短这个普通镜像文件。
执行一次即可，然后继续下面的检查。不需要手工 `truncate`。

```bash
e2fsck -fn la-rootfs.img
echo $?
stat -c %s la-rootfs.img
```

`e2fsck -fn` 完整只读复查；这里的退出码必须为 `0`，否则停止。
`stat -c %s` 显示缩容后文件的字节数，留作板端容量比较。

本次宿主机使用 e2fsprogs 1.47.2 的实测结果：

| 项目 | 结果 |
| --- | --- |
| 原镜像逻辑大小 | 15,032,385,536 字节（14 GiB） |
| 执行一次 `resize2fs -M` 后的大小 | 9,151,979,520 字节（约 8.52 GiB） |
| 缩容后复查 | Pass 1–5 完成，退出码 `0` |
| 本地副本扩容验证 | 扩到 18 GiB 后 Pass 1–5 完成，退出码 `0`；不是实板结果 |

以上大小对应本次输入镜像；换镜像时以实际 `stat` 输出为准。

## 2. 宿主机：启动网络传输

沿用现有直连配置：宿主机 `enp3s0` 为 `192.168.88.1`，板端 `eth0` 为 `192.168.88.2`。
在上一步的宿主机终端继续执行，当前目录为 `moss/rootfs/`：

```bash
sudo ip addr replace 192.168.88.1/24 dev enp3s0
sudo ip link set enp3s0 up
python3 -m http.server 8000 --bind 192.168.88.1
```

两条 `ip` 命令设置直连地址、启用网口；`python3` 用 HTTP 提供当前目录中的 `la-rootfs.img`，
`8000` 是端口，`--bind` 指定直连地址。保持这个终端运行。

## 3. 连接串口并校时

保持 HTTP 服务终端运行，另开一个**宿主机终端**连接串口：

```bash
picocom -b 115200 /dev/ttyUSB0
```

`-b 115200` 设置串口波特率，`/dev/ttyUSB0` 是连接板子的串口设备。
进入板端原厂 Linux，看到 `[root@LS-GD ~]#` 后，保持串口连接。

再开一个**宿主机终端**，确认时间正确后生成板端校时命令：

```bash
date -u '+date -u -s "%Y-%m-%d %H:%M:%S"'
```

`-u` 使用 UTC，格式化字符串生成带引号的 `年-月-日 时:分:秒`，`-s` 用于设置时间。
复制输出的完整一行，保留双引号，切回串口终端，在 `[root@LS-GD ~]#` 下粘贴并回车。

校时完成后再执行下面的板端命令。板端时间落后会使文件系统检查时间早于镜像的最后挂载时间，
导致 `resize2fs` 在检查完成后仍提示先运行 `e2fsck -f`。

## 4. 板端：确认目标并解除占用

通过串口进入原厂 Linux，在 `[root@LS-GD ~]#` 下执行：

```bash
lsblk -b -o NAME,SIZE,MOUNTPOINT /dev/sda
```

`-b` 以字节显示容量，`-o` 只显示设备名、容量和挂载点。必须看到 `/` 在 `sda1`，
且 `sda2` 的容量不小于宿主机记录的镜像字节数。此处只核对一次，不改分区。

```bash
ip addr replace 192.168.88.2/24 dev eth0
ip link set eth0 up
```

第一条设置板端直连地址，第二条启用网口。
此处注意：网线需连接至远离电源的网口，连错网口会导致后续无法从宿主机下载镜像并烧录。

```bash
systemctl stop systemd-udevd-control.socket systemd-udevd-kernel.socket
systemctl stop systemd-udevd.service
```

第一条停止两个激活 socket，第二条停止设备管理服务，防止烧录期间自动挂载。现场曾确认 `systemd-udevd`
在自己的挂载命名空间中把 `sda2` 挂到 `/media/usb0`，当前 shell 的 `findmnt` 看不到它。
停止服务会释放其自身保留的挂载环境；下面仍须确认没有其他残留挂载。
服务停止期间不插拔设备，最后会恢复服务。

```bash
umount /dev/sda2
```

卸载当前环境中的 `sda2`。若只提示 `not mounted`（未挂载），说明本来就没有挂载，继续下一步；
如果提示 `busy` 或其他错误，停止处理。

```bash
awk '$3 == "8:2" { print FILENAME, $0 }' /proc/[0-9]*/mountinfo
```

`8:2` 是本机 `/dev/sda2` 已确认的设备号。这条命令按设备号检查所有可见进程的挂载记录，
必须没有输出、没有报错。有输出就仍未卸载干净，不能写盘；不依赖板上缺失的 `nsenter`。

## 5. 板端：直接烧录缩容后的镜像

```bash
busybox wget -O /dev/sda2 http://192.168.88.1:8000/la-rootfs.img
echo $?
sync
```

`wget -O /dev/sda2` 把下载内容直接写入目标分区。`echo $?` 必须输出 `0`，然后用 `sync`
把写入刷到磁盘。目标必须是 `/dev/sda2`，网址必须是缩容后的 `la-rootfs.img`，不能填写 `.gz`。

下载失败、断网或退出码非 `0` 时，不挂载、不扩容；恢复网络后从本节开头重新完整烧录。
不要使用续传。这里写入的是完整文件系统，旧 `sda2` 的错误不需要在覆盖前再修复。

## 6. 板端：检查并扩容

保持 `/dev/sda2` 未挂载，先执行：

```bash
e2fsck -fp /dev/sda2
echo $?
```

`-f` 强制检查，`-p` 自动处理可安全修复的问题；只在退出码为 `0` 或 `1` 时继续。
如果新烧录的镜像仍报告大量重复块、损坏目录或 `is in use`，停止处理。

```bash
resize2fs /dev/sda2
```

resize2fs 工具自动把文件系统扩展到现有 `sda2` 的全部大小。
这只扩大文件系统，不改变分区表。

```bash
e2fsck -fn /dev/sda2
echo $?
```

`-fn` 完整只读复查，必须完成五个检查阶段、没有挂载警告，退出码为 `0`。
`aborted`、`Filesystem still has errors` 或退出码非 `0` 都不算成功。

## 7. 板端：挂载使用并恢复服务

```bash
mkdir -p /mnt/starry
mount /dev/sda2 /mnt/starry
df -h /mnt/starry
```

第一条创建挂载目录，第二条挂载已经检查通过的文件系统，第三条以易读单位显示扩容后的容量。
镜像里的 `/work` 此时对应 `/mnt/starry/work`。

```bash
systemctl start systemd-udevd-control.socket systemd-udevd-kernel.socket
systemctl start systemd-udevd.service
```

第一条恢复两个 socket，第二条恢复设备管理服务。烧录中途停止操作时，也应在确认没有写盘任务运行后恢复这些服务。
宿主机 HTTP 终端按 `Ctrl+C` 结束服务。

后续启动 MOSS 使用 `root=/dev/sda2`，按[启动指令](2K1000LA板-启动指令.md)操作。
